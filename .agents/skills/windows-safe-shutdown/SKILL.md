# 원격 Windows 작업 저장과 안전한 종료

사용자의 종료 요청을 받아 저장, Git 업로드, 프로그램 정상 종료, Windows 종료까지 수행한다. 커밋 메시지와 브랜치는 선택 입력이며 생략 시 실제 변경점으로 메시지를 작성하고 `main`을 사용한다. 사용자 지시가 우선한다. 스킬을 만들거나 설명하는 요청 자체는 커밋·push 또는 컴퓨터 종료의 실행 요청이 아니다.

## 대상과 접근 확인

- 원격 세션의 컴퓨터 이름·운영 체제, 저장소 실제 경로, Rider와 Unreal Editor가 연결된 호스트·프로젝트를 확인한다. Windows에서는 `$env:COMPUTERNAME` 등으로 대상 이름을 확인하되 전체 환경 변수나 자격 증명을 출력하지 않는다.
- 종료 대상은 사용자가 작업하던 원격 Windows 컴퓨터다. Codex가 Linux 클라우드에서 실행된다면 로컬 셸로 원격 컴퓨터를 종료할 수 있다고 가정하지 않는다. 실제 연결된 원격 실행 도구와 에디터 도구를 사용한다.
- 도구 목록과 지원되는 저장·종료 기능을 확인한다. 존재하지 않는 MCP 호출이나 Rider API를 만들지 않는다. 연결된 호스트가 서로 다르거나 종료 대상이 불명확하면 대상 확인만 요청하고 독립적인 읽기 작업을 계속한다.
- 저장하거나 업로드해야 할 프로젝트와 저장소를 확인한다. 다른 프로젝트의 미저장 내용을 버리거나 관련 없는 변경을 임의로 커밋하지 않는다.

## 실행 순서

### 1. Rider와 Unreal 작업 저장

- 먼저 Git 상태와 실행 중인 빌드·PIE·에셋 처리·Git 전송 작업을 확인한다. 완료를 기다리거나 지원되는 정상 중단 기능을 사용한다. 처리 중인 에셋이나 파일을 강제로 닫지 않는다.
- 연결된 Rider의 지원 도구 또는 실제 UI에서 Save All을 실행하고 미저장 문서가 없는지 확인한다. 자동 저장 설정이나 단순 대기만으로 저장 완료를 판단하지 않는다.
- Unreal Editor에서 PIE·시뮬레이션을 정상 중지하고 Save All을 실행한다. 수정된 맵·Blueprint·Content 에셋과 외부 액터 패키지 등 실제 dirty 패키지를 확인해 저장한다. Save Content만으로 맵 저장까지 보장하지 않는다.
- 저장 실패, 읽기 전용 파일, 이름 없는 파일의 저장 위치 질문, 체크아웃 문제 또는 해결되지 않은 dirty 상태가 있으면 해당 프로그램 종료와 Windows 종료를 진행하지 않는다. 사용자가 필요한 위치·선택을 지정할 때까지 데이터를 보존한다.
- **저장은 최종 커밋보다 먼저 수행한다.** 저장 전 Git 변경만 업로드하면 미저장 코드·에셋이 누락되므로, 모든 저장이 끝난 디스크 상태를 기준으로 업로드한다.

### 2. 커밋과 push

- [git-commit-push](../git-commit-push/SKILL.md)를 읽고 사용한다. 해당 스킬의 메시지 형식, 계정·브랜치 기본값, 변경 범위, 인증·LFS·실패 처리 규칙을 따른다.
- 저장 후 Git 변경과 기존 미푸시 커밋을 확인한다. 요청 범위의 변경이 있으면 실제 diff를 검토해 커밋하고 push한다. 새 변경 없이 미푸시 커밋만 있으면 push만 수행하며, 둘 다 없으면 빈 커밋을 만들지 않는다.
- 저장소의 관련 변경이 stage 대상에서 제외되거나 무시되는 경우 경로와 이유를 확인한다. 로컬 설정·비밀값·생성물을 업로드하기 위해 ignore 규칙을 임의로 바꾸지 않는다. 남겨도 되는 로컬 파일과 보존이 필요한 작업물을 구분한다.
- push 성공 출력과 종료 코드를 확인한다. 인증·충돌·LFS·hook 오류가 남으면 프로그램 및 Windows 종료를 멈추고 로컬 저장·커밋 상태와 정확한 차단 원인을 보고한다. 종료 요청을 Git 업로드 실패를 무시하라는 허가로 해석하지 않는다.

### 3. 프로그램 정상 종료와 마지막 확인

- Rider와 Unreal Editor의 지원되는 정상 종료 기능 또는 UI의 종료 동작을 사용한다. 미저장 확인 창이 나타나면 저장을 선택하며, Discard나 Don't Save를 자동으로 선택하지 않는다.
- 저장·종료 완료를 기다리고 대상 프로젝트의 프로그램 프로세스가 종료됐는지 확인한다. `taskkill /F`, 강제 프로세스 kill 또는 OS 강제 종료로 대신하지 않는다.
- 닫는 과정에서 추가 저장이 발생하면 Git 상태를 다시 확인한다. 새로 생긴 관련 변경은 git-commit-push 스킬로 처리하고 push 성공을 확인한 뒤 진행한다. 지속적으로 변경이 생기면 원인을 확인하고 종료를 보류한다.
- 파일 저장·빌드·에셋 처리·Git 전송이 남아 있지 않은지 확인한다. 다른 프로그램의 미저장 작업이 발견되면 강제 종료하지 않는다. 확인 도구가 부족하면 완료를 추측하지 말고 남은 확인 항목을 사용자에게 알린다.

### 4. Windows 종료

- 사용자에게 대상 컴퓨터 이름, 저장·커밋·push 결과와 프로그램 종료 상태를 짧게 알린 뒤 종료 명령을 실행한다. 명확한 종료 요청과 대상 확인이 있으면 같은 종료 승인을 다시 묻지 않는다. 플랫폼의 실제 권한 승인이 필요한 경우에는 그 절차를 따른다.
- 확인된 원격 Windows 호스트에서 `shutdown.exe /s /t 0`을 실행한다. `/f`는 사용하지 않는다. Windows는 양수 `/t` 값에 강제 종료가 암묵적으로 적용될 수 있으므로 지연 타이머를 안전장치로 사용하지 않는다.
- 종료 직전까지 접근이 가능해야 한다. 원격 연결 자체를 먼저 끊고 나서 종료를 시도하지 않는다. 다른 사용자 세션이나 미저장 작업 때문에 Windows가 종료를 막으면 이를 우회하지 않는다.
- 명령 성공은 종료 요청 수락을 의미한다. 연결이 끊겼다는 사실만으로 전원이 완전히 꺼졌다고 단정하지 않는다. 독립적인 원격 상태 확인 기능이 있을 때만 실제 종료 여부를 추가 확인한다. 종료 중 연결이 끊기면 상태를 확인하기 전 같은 명령을 반복하지 않는다.

## 완료 보고

대상 컴퓨터, 저장한 프로젝트, 커밋 SHA·브랜치·push 결과, 프로그램 종료와 Windows 종료 요청 결과를 간결하게 보고한다. 확인하지 못한 전원 상태는 구분해 적는다. 막혔다면 데이터가 어디까지 저장·업로드됐는지와 필요한 다음 조치만 알린다. 스킬 추가 작업만 수행한 경우 실제 원격 접속·저장·프로그램 종료·Windows 종료를 검증했다고 쓰지 않는다.
