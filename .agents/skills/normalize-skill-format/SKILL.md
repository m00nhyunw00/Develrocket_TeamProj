# 스킬 형식 점검 및 정리

스킬의 실제 기능과 실행 정책을 보존하면서 필수 메타데이터 및 한국어 UI 표시 형식을 보완한다. 여기서 정규 형식은 `SKILL.md`와 `agents/openai.yaml`을 갖춘 구성을 뜻한다. YAML이 없는 스킬 자체가 무효라는 뜻은 아니다.

## 대상 선택

- 대상 없이 사용하면 현재 프로젝트 루트의 `.agents/skills` 안에 존재하는 모든 스킬을 검사한다. `.agent` 또는 전역 스킬 폴더로 대체하지 않는다.
- 스킬 본명, 폴더명 또는 한국어 표시 이름을 지정하면 해당 스킬만 검사한다. 이름이 여러 개면 지정한 스킬들만 처리한다.
- 표시 이름은 `agents/openai.yaml`의 `interface.display_name`, 본명은 `SKILL.md`의 `name`으로 확인한다. 중복 이름으로 대상이 불명확하면 경로를 확인한다.
- 명시적인 경로가 주어지면 그 범위를 사용한다. 프로젝트 경로나 스킬 폴더를 찾지 못하면 새 빈 폴더를 만드는 대신 실제 위치를 확인한다.
- 심볼릭 링크나 정션은 실제 위치를 확인한다. 프로젝트 밖의 설치 원본까지 변경하게 된다면 영향 범위를 설명하고 대상에 포함할지 확인한다.
- 스킬 파일을 읽는 것은 검사 목적이다. 대상 스킬의 명령, 배포, 커밋, 종료 등의 기능을 실행하지 않는다.

## 확인할 형식

```text
skill-name/
├─ SKILL.md
└─ agents/
   └─ openai.yaml
```

1. `SKILL.md`의 YAML frontmatter에 비어 있지 않은 `name`과 `description`이 있는지 검사한다. 이름은 소문자·숫자·하이픈을 사용하는 식별자로 유지한다.
2. `agents/openai.yaml`에 `interface.display_name`, `interface.short_description`, `interface.default_prompt`가 있는지 확인한다.
3. 표시 이름과 설명, 기본 프롬프트는 스킬의 실제 기능에 맞는 한국어로 작성한다. 제품명이나 기술 식별자는 원문을 유지할 수 있다.
4. `short_description`은 25~64자로 작성한다. `default_prompt`에는 실제 본명인 `$skill-name`을 포함한다. 원래 기능에 없던 실행이나 권한을 기본 프롬프트에 추가하지 않는다.
5. YAML 문자열은 따옴표로 감싸고, 키는 따옴표 없이 작성한다. 스크립트와 참고 자료 등 기존 선택 리소스는 유지하며 불필요한 빈 폴더는 만들지 않는다.

## 수정 원칙

- 먼저 현재 파일 및 Git 변경 상태를 읽는다. 누락·형식 오류·영어 표시 등 발견한 문제에 필요한 부분만 수정한다. 이미 적합한 파일은 그대로 둔다.
- 스킬의 본명, 폴더명, 기능 지침, 사용자 기존 변경을 보존한다. 설명을 한국어로 다듬더라도 자동 선택 조건과 제외 조건을 바꾸지 않는다.
- `policy`, `dependencies`, 아이콘, 색상 등 기존 YAML 필드를 보존한다. 전체 YAML을 단순히 재생성해 덮어쓰지 않는다.
- 실행 정책이 명시적 호출 전용이면 그대로 유지한다. 누락된 YAML을 만들 때도 `disable-model-invocation: true` 같은 기존 설정이 있다면 그 의도를 `policy.allow_implicit_invocation: false`에 반영한다. 이를 이유로 기존 frontmatter 필드를 임의 삭제하지 않는다.
- 본명 누락은 폴더명과 본문으로 확실히 판단할 수 있을 때만 보완한다. 기존 이름 충돌이나 참조를 깨뜨리는 이름 변경은 자동으로 하지 않는다.
- `SKILL.md`가 없는 폴더는 리소스 폴더일 수 있다. 기능을 추측해 새 스킬로 만들지 말고 검사 결과에 구분해 기록한다.
- 형식 검증기가 다른 런타임의 확장 필드를 거부하면 필드를 무조건 삭제하지 않는다. 호환성 문제와 기능 보존을 구분하여 보고한다.
- 파일 편집에는 최소 패치 또는 기존 필드를 보존하는 편집을 사용한다. 보호된 경로의 권한 오류는 정해진 승인 절차로 처리하고 다른 위치에 우회 복사하지 않는다.

## 검증과 결과

- 실행 환경에서 `skill-creator`를 사용할 수 있으면 UI 메타데이터 사양을 참고하고, 새 YAML에는 제공되는 생성기를 활용한다. 기존 YAML은 필요한 필드만 갱신한다.
- YAML 파서를 사용할 수 있으면 구문과 필드 타입을 검사한다. `quick_validate.py`를 사용할 수 있으면 SKILL.md도 검사한다. 검증 도구가 없으면 설치를 강제하지 않고 수행한 구조 검사와 미실행 검증을 구분한다.
- 수정 후 한국어 표시, 본명과 기본 프롬프트의 일치, 기존 실행 정책·의존성 보존, 변경 범위를 확인한다.
- 변경 전후 비교로 무관한 본문이나 리소스를 수정하지 않았는지 확인한다. 게임 코드 빌드나 대상 스킬 실제 실행은 필요하지 않다.
- 최종 응답은 검사한 개수, 수정한 개수와 `스킬 본명 | 한국어 표시 이름 | 보완 사항` 표로 간결하게 정리한다. 변경이 없으면 이미 형식을 충족한다고 보고한다. 해결하지 못한 문제는 별도로 명시한다.
