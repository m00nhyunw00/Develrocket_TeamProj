# 최신 변경 받아오기

사용자가 요청한 pull을 추가 확인 없이 진행한다. 기본 대상은 **원격 origin/main과 로컬 main**이며, 사용자가 지정한 저장소·원격·브랜치·병합 방식이 우선한다. 이 스킬을 만들거나 수정하는 요청 자체로 프로그램 종료나 pull·커밋·push를 실행하지 않는다.

## 기본 계정과 브랜치

- 브랜치를 생략하면 현재 브랜치나 upstream 설정과 관계없이 `main`을 대상으로 한다. 다른 브랜치에서 `git pull origin main`을 실행해 main의 변경을 섞지 않는다. 작업 트리가 깨끗하면 로컬 `main`으로 전환한 뒤 갱신한다.
- 브랜치를 명시하면 해당 로컬 브랜치와 원격 브랜치를 대상으로 한다. 사용자가 현재 브랜치에 다른 브랜치를 병합하라고 명시한 경우에는 그 지시를 따른다.
- GitHub HTTPS 인증 계정은 기본 `m00nhyunw00`다. 네트워크 작업 전에 원격 주소와 저장소의 계정 설정을 확인하고, 필요한 경우에만 다음 로컬 설정을 적용한다.

  ```powershell
  git config --local credential.https://github.com.username m00nhyunw00
  ```

- 전역 설정, 다른 계정의 자격 증명, `user.name`·`user.email`은 변경하지 않는다. 토큰이나 비밀번호를 출력하지 않는다.
- Git 네트워크 명령에는 `-c credential.interactive=false`를 사용하고 해당 실행 프로세스에서만 `GIT_TERMINAL_PROMPT=0`을 적용한다. 기존 환경값을 바꿨다면 작업 후 복원한다. 인증 실패 시 계정 선택 창을 반복해서 띄우거나 다른 계정으로 재시도하지 않는다.

## 빠른 기본 절차

1. **프로그램 확인과 종료부터:** Git 네트워크 작업에 앞서 대상 프로젝트의 Unreal Editor와 Rider가 실행 중인지 먼저 확인한다. 실행 중이면 아래 **Unreal Editor·Rider 종료** 절차로 두 프로그램을 정상 종료하고 종료 여부를 확인한다. 최신 여부나 수신 파일 종류에 따라 이 단계를 생략하지 않는다. 둘 다 실행 중이지 않으면 바로 다음 단계로 넘어간다.
2. **Git 상태 확인:** 프로그램 종료 후 `git status --short --branch --untracked-files=all`, 현재 브랜치, 원격 주소, 대상 로컬 브랜치의 존재 여부를 한 번에 확인한다. 진행 중인 merge·rebase·cherry-pick이나 미해결 충돌도 확인한다. 종료 과정에서 저장된 파일도 로컬 변경에 포함한다. 전체 코드·에셋 분석은 하지 않는다.
3. **로컬 작업 보존:** staged·unstaged·미추적 변경이나 진행 중인 Git 작업이 있으면 브랜치 전환과 pull을 하지 않는다. 사용자가 보존·정리 방법을 이미 지시했다면 그 범위에서 처리하고, 그렇지 않으면 현재 상태와 필요한 조치를 짧게 알린다. 필요할 때 원격 상태 확인을 위한 fetch까지만 수행할 수 있다.
4. **대상 전환:** 작업 트리가 깨끗하고 대상 브랜치가 있으면 `git switch <대상 브랜치>`로 전환한다. 이미 해당 브랜치이면 전환을 생략한다. 다른 worktree가 사용하는 브랜치를 강제로 체크아웃하지 않는다.
5. **최신 변경 반영:** 기본 main에서는 다음 명령으로 fast-forward만 허용한다. 명시한 다른 브랜치는 원격과 브랜치 인수를 바꿔 실행한다. 기존 설정에 따른 자동 rebase·stash를 막고, 명령 종료 코드를 확인한다.

   ```powershell
   git -c credential.interactive=false pull --ff-only --no-rebase --no-autostash origin main
   ```

   대상 로컬 브랜치가 없다면 먼저 해당 원격 브랜치를 fetch해 존재와 최신 참조를 확인하고, `git switch --track -c <대상 브랜치> <원격>/<대상 브랜치>`로 만든다. 이 경우 이미 받은 커밋에서 시작하므로 같은 내용을 다시 pull하지 않는다. 원격 브랜치가 없으면 임의의 시작점에서 새 브랜치를 만들지 않는다.

   확인 목적으로 이미 fetch했다면 그 최신 원격 추적 참조를 대상으로 `git -c merge.autoStash=false merge --ff-only <원격>/<대상 브랜치>`를 실행해 중복 fetch를 생략할 수 있다. 이때도 대상 로컬 브랜치로 전환한 상태여야 한다.

6. **결과 확인:** 종료 코드와 Git 출력, 마지막 `git status --short --branch`, 최종 HEAD로 성공 여부와 남은 변경을 한 번 확인한다. 갱신한 원격/로컬 브랜치, 이전→최종 커밋과 반영 결과를 짧게 보고한다. 이미 최신이면 그대로 알린다. 로컬에만 있는 커밋은 유지하고, 남아 있다는 사실을 구분해 알린다.

## Unreal Editor·Rider 종료

- **실행 확인:** 실행 파일·명령줄·프로젝트 경로와 창 정보를 이용해 대상 프로젝트의 Unreal Editor와 Rider를 식별한다. 창이 없거나 응답이 없는 잔류 프로세스도 포함한다. 프로세스 조회가 권한 문제로 실패하면 필요한 접근 권한을 확보하며, 조회 실패를 미실행으로 판단하지 않는다. 다른 프로젝트의 프로그램이나 공용 백엔드 프로세스는 일괄 종료하지 않는다.
- **미저장 작업 확인:** Unreal은 기존 연결에서 `EditorLoadingAndSavingUtils.get_dirty_content_packages()`와 `get_dirty_map_packages()`를 한 번 확인하고, Rider는 수정 중인 문서와 저장 상태를 확인한다. Git 작업 트리가 깨끗하다는 사실만으로 프로그램에 미저장 작업이 없다고 판단하지 않는다. 확인을 위해 에디터를 새로 실행하거나 엔진 소스·통신 방식 등을 장시간 조사하지 않는다.
- **보존 방법 적용:** 미저장 작업이 있으면 사용자가 이미 승인한 저장·보존·폐기 방법을 따른다. 지시가 없거나 상태를 확인할 수 없어 작업 손실 가능성을 판단할 수 없으면, 해당 프로그램과 확인된 상태를 짧게 알리고 필요한 처리 방법만 묻는다. 임의 저장·폐기로 우회하지 않는다. 이미 받은 승인은 다시 묻지 않는다.
- **정상 종료:** 보존 처리가 끝났거나 미저장 작업이 없으면 **추가 확인 없이 대상 Unreal Editor와 Rider를 정상 종료한다.** 이는 pull 요청에 포함된 동작이다. 지원되는 종료 API나 창 닫기를 사용한다. Rider에 여러 프로젝트가 열려 있으면 대상 프로젝트 창만 닫고 다른 프로젝트는 유지한다.
- **종료 확인과 시간 제한:** 확인한 PID·프로젝트 창이 종료되고 파일 잠금이 해제됐는지 확인한 뒤 진행한다. 정상 종료 요청 후 10~15초 정도 기다려 확인하고, 계속 실행 중이면 저장 대화상자나 응답 정지를 한 번 확인한다. 같은 종료 요청이나 대기를 반복하지 않는다. 강제 종료가 필요하면 이미 받은 명시적 승인을 적용하고, 승인이 없으면 미저장 작업 손실 가능성과 대상 프로세스를 알린 뒤 한 번만 확인받는다. 창만 사라진 잔류 프로세스를 종료 완료로 간주하지 않는다.
- **종료 후 진행:** 대상 프로그램의 종료가 확인되기 전에는 pull·merge·브랜치 전환을 시작하지 않는다. 종료 후 Git 상태를 확인해 저장으로 생긴 변경도 보존한다. 사용자가 요청하지 않은 프로그램 재실행은 하지 않는다.

## 실패와 예외

- 원격과 로컬 이력이 갈라져 fast-forward가 불가능하면 커밋을 보존하고 중단한다. 이미 가져온 참조로 ahead/behind와 분기 원인을 확인하며 같은 pull을 반복하지 않는다. 사용자가 별도 지시하지 않은 merge commit·rebase·reset·stash·clean·force 옵션으로 맞추지 않는다.
- 네트워크·인증·LFS·hook 오류는 필요한 범위만 조사한다. LFS 다운로드나 checkout에서 실패했다면 HEAD와 작업 트리를 확인해 일부 반영 여부를 알리고, pull이 모두 완료됐다고 보고하지 않는다.
- Git LFS는 저장소의 기존 필터와 설정을 유지한다. skip-smudge나 전체 LFS 재다운로드를 기본 절차에 추가하지 않는다. 사용자의 별도 지시나 실제 누락 문제가 있을 때만 해당 범위의 LFS 파일을 받는다.
- 파일 잠금으로 실패했다면 대상 Unreal Editor·Rider의 잔류 프로세스를 위 절차로 처리하고, 사전 HEAD·Git 상태와 비교해 부분 반영 여부를 확인한다. 이번 실패가 만든 변경만 원격 내용과 대조하고 백업한 뒤 복구한다. 출처가 불분명하거나 동시에 수정된 파일은 보존한다. 전체 reset·clean으로 정리하지 않는다. 잠금 해제와 로컬 변경 보존을 확인한 뒤 이미 받은 원격 참조로 fast-forward를 한 번 재시도하고, 다시 실패하면 원인을 보고한다.
- pull만 요청받은 경우 커밋·push, Unreal 빌드·플레이, 불필요한 테스트·웹 검색·서브에이전트·새 worktree를 추가하지 않는다. Git hook은 정상 실행되도록 둔다.
