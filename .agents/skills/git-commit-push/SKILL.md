# 빠른 한국어 커밋과 푸시

사용자가 요청한 커밋·push를 추가 확인 없이 완료한다. 일반적인 요청은 **같은 저장소 작업 폴더에 실행 시점까지 쌓인 저장된 변경 전체**를 짧게 검토하고 **커밋 1개와 push 1회**로 처리한다. 현재 채팅방에서 만든 변경뿐 아니라 다른 채팅방·도구·사용자가 만든 변경도 포함하며, 작업 출처가 다르다는 이유로 제외하거나 다시 확인받지 않는다. 별도 worktree·다른 컴퓨터의 변경을 자동으로 가져오지는 않는다. 사용자에게 별도 계정·브랜치·범위·분할 지시가 있으면 그 지시가 우선한다.

## 기본 계정과 브랜치

- 대상은 기본 `origin/main`, GitHub HTTPS 인증 계정은 `m00nhyunw00`다.
- GitHub HTTPS 원격은 네트워크 작업 전에 저장소의 기본 인증 계정을 확인하고, 필요한 경우에만 아래 로컬 설정을 적용한다. 저장된 해당 계정을 사용해 계정 선택 창을 생략한다.

  ```powershell
  git config --local credential.https://github.com.username m00nhyunw00
  ```

- 전역 설정, 다른 계정의 자격 증명, 커밋 작성자 `user.name`·`user.email`은 변경하지 않는다. 토큰이나 비밀번호를 출력하지 않는다.
- Codex가 실행하는 Git 네트워크 명령에는 `-c credential.interactive=false`를 사용하고 해당 프로세스에서만 `GIT_TERMINAL_PROMPT=0`을 적용한다. 기존 자격 증명으로 처리하고, 인증이 실패하면 계정 창을 반복해서 띄우거나 다른 계정으로 재시도하지 않는다. 재로그인·2FA가 실제로 필요한 경우에만 사용자에게 알린다.
- 현재 브랜치가 `main`이면 사전 fetch 없이 일반 push한다. 원격과의 충돌은 강제 옵션 없는 push가 차단한다. 다른 브랜치라면 원격 main과의 관계와 미푸시 커밋 범위를 확인하고, 확인에 필요한 경우만 fetch한다. 관련 없는 커밋이 섞인 브랜치를 main으로 밀어 넣지 않는다.

## 빠른 기본 절차

1. **한 번에 확인:** `git status --short --branch --untracked-files=all`과 필요한 원격 정보, staged·unstaged 텍스트 diff를 묶어서 확인한다. 같은 내용을 반복 조회하지 않는다. 이미 검토한 변경은 재사용하고 이후 차이만 확인한다. 미추적 파일은 이름·종류를 먼저 보고 필요한 파일만 읽는다. 최초 확인한 파일 목록과 변경 내용을 이번 커밋의 기준으로 삼는다.
2. **전체 변경과 메시지 결정:** 별도 범위 지시가 없으면 staged·unstaged·미추적 파일의 추가·수정·삭제 전체를 한 커밋으로 묶는다. 기존 staged 선택만으로 범위를 좁히지 않으며, 다른 채팅방의 작업이나 서로 다른 작업 주제도 포함한다. 아래 제외 대상은 지킨다. 사용자가 특정 파일·작업만 지정하거나 분할을 요청한 경우에만 그 지시를 우선한다. 전체 diff와 에셋·파일 목록에서 변경 주제를 파악해 커밋 메시지에 모두 반영한다.
3. **최소 검사:** 대상 파일 경로를 명시해 stage하고 staged 목록과 `git diff --cached --check`를 한 번 확인한다. 검토한 텍스트 diff를 다시 전부 출력하지 않는다. 검사에서 발견한 새 줄의 끝 공백은 필요한 부분만 정리하되 기능 수정은 끼워 넣지 않는다.
4. **커밋 후 즉시 push:** UTF-8 임시 메시지 파일을 `git commit -F <파일>`로 전달한다. 성공한 경우에만 `git -c credential.interactive=false push origin main`을 실행한다. 다른 브랜치에서는 대상과 outgoing 범위를 확인한 경우에만 적절한 명시적 refspec을 사용한다. 각 명령의 종료 코드를 확인한다.
5. **한 번만 확인하고 종료:** push 성공 출력과 종료 코드로 업로드 성공을 판단하고 마지막 `git status --short --branch`로 남은 변경을 확인한다. 성공 후 `ls-remote`, 재-fetch, LFS 전체 검사를 추가하지 않는다. 브랜치·커밋 SHA·제목·push 결과를 짧게 보고한다.

변경이 없으면 빈 커밋을 만들지 않는다. 대상 브랜치에 기존 미푸시 커밋이 있으면 push만 한다. 최초 확인 이후 생긴 변경은 이번 커밋에 섞지 않는다. 같은 파일이 동시에 수정돼 처음 확인한 내용만 분리할 수 없으면 해당 변경을 보존하고 남은 범위를 알린다.

## 기본 흐름에서 생략할 작업

- Rider 파일별 정적 검사, Unreal 전체 빌드, 테스트·플레이 실행, 에디터 접속과 BP/CDO·애셋 레지스트리 검사. 사용자가 검증을 요청했거나 별도 필수 검사·실제 오류가 있을 때만 수행하며, 기존 Git hook은 그대로 실행한다.
- 미저장 에디터 파일·에셋 탐색과 자동 저장. 커밋 요청은 디스크에 저장된 Git 변경을 대상으로 한다. 저장까지 요청한 경우에만 수행한다.
- 바이너리 에셋 내용 분석, LFS 포인터 파일별 순회 검사, 전체 저장소 무결성 검사. 에셋 경로와 기존 `.gitattributes` 규칙을 확인하고 Git LFS의 정상 add·push 경로를 사용한다.
- 불필요한 웹 검색, 전체 소스·문서 재독, 서브에이전트, 새 worktree, 반복 진행 보고. 단순 커밋은 시작 안내와 결과 위주로, 실제 대기가 길어지면 필요한 진행 상황만 전달한다.

## 커밋 메시지

- 제목: `<유형>: <한국어 요약>`. 유형은 `Add`, `Update`, `Fix`, `Refactor`, `Optimize`, `Remove`, `Docs`, `Test`, `Build`, `Chore` 중 주된 변경 목적에 맞게 선택한다.
- 제목 다음 빈 줄 뒤에 한국어 설명을 먼저 쓰고, 빈 줄로 구분해 같은 의미의 영어 설명을 이어 쓴다. `한국어:`, `English:` 같은 언어 제목은 붙이지 않는다. 각 언어에 포함된 모든 변경 주제를 간결한 항목으로 담는다. 현재 채팅방의 작업만 요약하거나 항목 수를 맞추려고 다른 작업을 누락하지 않는다. 파일별 나열 대신 관련 변경끼리 묶되 제목과 본문을 합쳐 전체 범위를 설명한다. 사용자가 준 메시지는 실제 diff에 맞게 다듬는다.
- 실제 변경만 요약한다. 실행하지 않은 검사 결과를 넣지 않으며, 커밋만 요청받았다면 검증 문구를 채우려고 새 검사를 시작하지 않는다.
- 메시지는 실제 줄바꿈이 있는 임시 파일로 작성한다. 셸 보간이나 명령 치환으로 메시지를 조립하지 않는다.

## 실패와 보존

- `git add .` 대신 검토한 파일 목록을 사용한다. 비밀값·로컬 설정·`Binaries`·`Intermediate`·`Saved`·`DerivedDataCache` 등 생성물을 포함하지 않는다. 요청한 게임 에셋은 기존 LFS 규칙을 유지한다.
- non-fast-forward 거절이면 그때 한 번 fetch해 분기를 확인한다. 인증·LFS·hook·브랜치 보호 오류는 원인에 필요한 범위만 조사하고 우회하거나 같은 실패 명령을 반복하지 않는다.
- 무단 reset·stash·rebase·amend·force push와 사용자 변경 삭제를 하지 않는다. 해결에 사용자 판단이 필요하면 로컬 커밋을 보존하고 실제 막힌 이유만 짧게 알린다.
- LFS 전송량과 네트워크·hook 실행 시간은 생략할 수 없다. 실제 측정 없이 특정 배수의 속도 향상을 약속하지 않는다.
