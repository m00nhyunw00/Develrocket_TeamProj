# 함수 인자 한 줄 정리

함수 호출의 인자 사이 및 여는·닫는 괄호 주변 줄바꿈을 제거한다. 줄 길이 때문에 다시 분리하지 않으며, 호출 첫 줄의 들여쓰기와 기존 코드 동작을 유지한다.

## 대상 선택

- **코드 제공:** 제공된 코드 범위만 정리하고 완성된 코드 블록을 응답한다. 파일 변경을 따로 요청하지 않았다면 프로젝트 파일을 수정하지 않는다. 채팅 붙여넣기의 명백한 HTML 공백·개행 이스케이프는 원래 코드로 복원하되, 문자열 내부의 실제 이스케이프는 유지한다.
- **파일 이름 또는 경로 제공:** 해당 프로젝트 파일을 찾아 직접 수정한다. 이름만 받으면 `rg --files`로 찾고, 동명 파일이 여러 개면 대화 맥락으로 확정하거나 대상 경로를 질문한다. 지정한 함수나 구간 제한이 있으면 그 범위만 수정한다.
- **대상 없이 스킬만 사용:** Rider의 `get_all_open_file_paths`를 호출해 현재 열린 파일을 매번 확인한다. 알려진 프로젝트 루트를 전달하고 활성 탭뿐 아니라 열린 모든 프로젝트 C++ 소스 파일을 대상으로 한다. 이전 대화의 목록이나 Git 변경 목록으로 대체하지 않는다. 연결할 수 없으면 임의로 프로젝트 전체를 수정하지 않고, 연결 또는 파일 지정을 요청한다.
- 코드와 파일을 함께 주면서 직접 편집을 요청했다면 파일 편집을 우선한다. 대상의 코드가 실제 파일과 다르면 현재 파일을 기준으로 요청 범위를 확인한다.

## 변환 범위

- 일반 함수·멤버 함수·템플릿 함수 호출의 인자 목록을 한 줄로 합친다. 중첩 호출도 괄호 구조를 확인하여 함께 정리한다.
- 콤마 뒤에는 공백 하나를 사용하고, 괄호 바로 안쪽의 줄바꿈용 들여쓰기는 제거한다.
- 인자 값·순서·개수, 함수명, 식별자, 연산자, 문자열 내용, 주석 내용은 변경하지 않는다.
- 함수 선언·정의의 매개변수 목록은 사용자가 함께 정리하도록 요청한 경우에만 포함한다. 조건문, 반복문, 함수 본문, 초기화 목록, 매크로 정의는 이 작업에 끼워 정리하지 않는다.
- `//` 주석 뒤 개행은 의미가 있으므로 제거하지 않는다. 인자 사이에 줄 주석이나 전처리 지시문이 있으면 해당 호출은 보존하고 이유를 짧게 보고한다. 개행이 포함된 raw 문자열과 여러 줄 람다 본문도 강제로 합치지 않는다. 안전하게 분리할 수 있는 다른 호출은 계속 정리한다.
- 여러 줄을 무차별 정규식으로 합치지 않는다. 문자열·주석·중첩 괄호를 구분하고 호출 단위로 변경한다.
- 전체 파일 포맷터, Rider 코드 정리, 프로젝트 스타일 설정 변경은 사용하지 않는다. 이 작업 때문에 다시 줄바꿈되거나 무관한 코드가 바뀌지 않도록 한다.

변환 예시:

```cpp
EnhancedInput->BindAction(
    JumpAction,
    ETriggerEvent::Started,
    this,
    &ATBPlayer::InputJumpStarted
);
```

```cpp
EnhancedInput->BindAction(JumpAction, ETriggerEvent::Started, this, &ATBPlayer::InputJumpStarted);
```

## 파일 편집 및 검증

1. 대상 파일의 현재 내용과 변경 상태를 읽는다. Rider의 미저장 편집 내용이 있다면 IDE 문서를 기준으로 안전하게 편집한다. 디스크와 에디터 내용이 달라 보존 여부를 확인할 수 없으면 해당 파일은 덮어쓰지 않고 저장을 요청한다.
2. 열린 파일 기본 모드에서는 프로젝트의 `.h`, `.hpp`, `.cpp`, `.cc`, `.cxx`, `.inl` 등 직접 작성한 C++ 파일만 처리한다. 생성 코드, 엔진·외부 라이브러리, 읽기 전용 파일은 제외한다.
3. 파일 도구를 사용하는 경우 `apply_patch`로 호출 부분만 최소 수정한다. 기존 사용자 변경, 인코딩, 줄바꿈 형식을 보존한다.
4. 작업 직전 내용과 비교하여 인자 목록의 공백·개행 외 코드가 바뀌지 않았는지 확인한다. 이미 변경된 파일의 Git diff 전체를 이번 수정으로 간주하지 않는다.
5. 대상 범위를 다시 확인해 정리 가능한 호출이 남지 않았는지 검사한다. 변경할 곳이 없으면 그대로 둔다. 서식 변경만으로 빌드나 실행을 요구하지 않는다.

## 응답

- 코드 제공 모드: 수정된 코드 블록을 우선 반환하고 불필요한 설명을 생략한다.
- 파일 편집 모드: 수정한 파일을 링크하고 결과를 간결한 한국어 존댓말로 보고한다. 건너뛴 부분이나 확인하지 못한 부분이 있다면 명시한다.
- 스킬 생성·수정 요청 자체는 실제 소스 정리 요청으로 취급하지 않는다.
