# 언리얼 코드 핵심 주석

블루프린트의 기본 개념은 익숙하지만 언리얼 C++은 학습 중인 개발자가, 나중에 코드를 다시 읽거나 다른 언리얼 개발자와 공유할 때 핵심 의도를 바로 이해할 수 있는 주석을 작성한다. 주석의 양보다 필요한 설명의 정확성과 가독성을 우선한다. 이번 요청에 별도 범위나 문체 지시가 있으면 그 지시를 우선한다.

## 대상 확인

- 파일이나 함수가 지정되면 해당 범위만 수정한다. “생성자만” 등의 제한도 그대로 적용한다.
- “지금 에디터에 열린 코드”는 Rider의 `get_all_open_file_paths`로 매번 확인한다. 알고 있는 프로젝트 루트를 전달하고, 이전 대화의 파일 목록이나 Git 변경 목록으로 대체하지 않는다.
- 열린 소스 파일만 대상으로 삼는다. 생성 코드, 외부 라이브러리, 에셋은 제외한다. `.h`, `.cpp` 외에 열린 `.Build.cs`도 요청 범위에 포함할 수 있다.
- 열린 파일 목록을 확인할 수 없으면 대상을 추측해 프로젝트 전체를 수정하지 말고, 파일 경로를 요청한다.
- 수정 전 현재 내용과 기존 변경 사항을 읽는다. 필요한 경우 관련 선언·호출부를 최소한으로 확인하되, 확인용으로 읽은 다른 파일까지 수정하지 않는다. 에디터와 디스크 내용이 달라 안전한 편집이 어려우면 사용자에게 저장을 요청한다.

## 문체와 밀도

- 한국어 명사형 종결 사용: `설정`, `연결`, `조회`, `캐싱`, `갱신`, `반환`, `해제`, `제외`, `복구` 등.
- `~합니다`, `~해 줍니다`, `~해야 됨` 등의 설명체·구어체는 새 주석에 사용하지 않는다.
- 의미 단위의 코드 묶음 위에 짧은 `//` 주석을 우선한다. 한 줄로 충분하면 여러 줄로 늘리지 않는다.
- 모든 줄·함수·멤버에 주석을 붙이지 않는다. 코드나 이름만으로 명확한 단순 대입, 반환, getter, 조건문은 보통 설명하지 않는다.
- Tick, BeginPlay 등 블루프린트에도 있는 익숙한 개념의 정의와 기본 호출 시점은 생략한다. 해당 함수 안의 프로젝트 고유 로직은 필요하면 설명한다.
- 식별자와 Unreal 용어는 필요한 만큼 그대로 사용한다. 불필요한 번역이나 같은 내용의 한영 반복은 피한다.

## 설명할 내용

- **의도와 효과:** 코드를 한국어로 한 줄씩 옮기기보다, 왜 필요한 처리인지와 게임 동작에 미치는 영향 설명.
- **흐름과 연결:** 컴포넌트 역할, 소유자 참조, 델리게이트 발신·수신, Notify와 판정 구간, 상태 전환, UI 갱신 등 코드만 보고 놓치기 쉬운 관계 설명.
- **조건과 순서:** 후보 제외 기준, 중복 처리 방지, 특정 순서가 필요한 이유, 참조 유효성을 확인해야 하는 실제 맥락 설명.
- **비자명한 계산:** 벡터·내적 등은 기준 방향, 비교 대상, 선택 결과를 중심으로 설명. 긴 수식 유도나 블로그식 강의는 코드 주석에 넣지 않는다.
- **헤더와 구현 분담:** 헤더는 역할·계약·데이터 의미, 구현은 핵심 처리 이유와 흐름 위주. 양쪽에 같은 설명을 반복하지 않는다.
- **생성자:** 컴포넌트 생성·부착, 입력·이동 정책, 이벤트 연결 등 중요한 설정 묶음의 목적만 설명. 모든 설정값을 개별 해설하지 않는다.

## 수치 처리

- 정말 핵심적인 의미가 있는 경우가 아니면 구체적인 수치를 주석에 넣지 않는다. 특히 긴 소수, 계산 결과, 알아보기 어려운 임계값을 그대로 나열하지 않는다.
- 이동 속도, 카메라 거리, 스태미나 비용, 배율 등 코드에 이미 있는 조정값은 반복하지 않고 용도나 의도를 설명한다.
- 정확한 값 없이는 알고리즘의 기준·단위·경계 조건을 오해하게 되는 경우에만 필요한 수치와 의미를 최소한으로 적는다.
- 수치의 선정 이유를 코드나 자료로 확인할 수 없으면 임의로 정당화하지 않는다.

## 기존 주석과 빈 주석

- 정확하고 유용한 기존 주석은 유지한다. 문체 통일만을 이유로 전체 주석을 다시 쓰지 않는다.
- 추가·변경된 로직에 설명이 없거나 기존 주석이 실제 동작과 어긋난 경우에만 보완한다.
- 내용 없는 `//`는 주변 코드의 의미를 확인해 작성한다. 설명할 내용이 없는 자리라면 의미 없는 문구로 채우지 말고 빈 주석 줄만 제거한다.
- 저작권, 도구 지시용 주석, 실제 TODO와 작성 중인 코드를 임의로 없애지 않는다.
- 구현되지 않은 기능이나 아직 연결되지 않은 경로를 이미 동작하는 것처럼 설명하지 않는다. 의도가 확실하지 않으면 확인 가능한 동작만 적는다.

## 수정과 검증

- 주석 작업은 주석만 수정한다. 함수명·시그니처, 조건, 수치, include, 리플렉션 지정자, 동작 로직과 관련 없는 포맷은 변경하지 않는다.
- 코드 문제가 보여도 주석 작업에 끼워 고치지 않는다. 중요한 문제는 근거와 함께 별도로 짧게 알린다.
- 기존 사용자 변경을 보존하고 `apply_patch`로 필요한 부분만 편집한다.
- 작업 직전 내용과 비교해 주석 외 코드가 그대로인지 확인한다. 이미 변경된 작업 트리에서는 Git HEAD와의 차이 전체를 이번 작업으로 간주하지 않는다.
- 대상 파일에 남은 빈 `//`와 주석의 사실관계를 재확인한다. 가능하면 Rider 코드 검사로 편집 후 오류를 확인한다. 주석만 바꾼 작업을 위해 에디터 실행이나 전체 빌드를 강제하지 않는다.
- 완료 보고는 대상 파일 수 또는 파일명, 주요 보완 내용, 코드 로직 변경 여부를 짧게 전달한다. 실제 수행한 검사만 보고하고 정적 검사를 빌드·실행 검증으로 표현하지 않는다.
