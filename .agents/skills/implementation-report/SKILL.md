# 핵심 구현 코드 보고서

실제 구현한 코드와 해결한 문제를 파일명별 코드 블록 중심의 간결한 보고서로 정리한다. 기본 산출물은 채팅에서 복사할 수 있는 Markdown이며, 사진은 사용자가 첨부할 수 있도록 촬영 대상을 글로 안내한다.

## 범위와 근거 확인

- 사용자가 파일·기능·날짜·커밋을 지정하면 그 범위를 우선한다. 대상 없이 호출하면 현재 대화에서 다룬 최근 구현을 중심으로 현재 파일과 Git 변경 기록을 확인한다. 오늘 작업 요청은 사용자의 시간대와 현재 날짜를 기준으로 조사한다.
- Git 작성일이나 수정일만으로 사용자의 오늘 구현이라고 단정하지 않는다. 대화와 diff를 함께 확인하고 팀원의 무관한 변경, 이전 작업, 아직 제안만 한 코드를 구분한다.
- 현재 코드를 보고한다. 직전에 주석이나 선언 배치를 정리했다면 정리가 끝난 파일을 다시 읽고 그 주석까지 포함해 발췌한다.
- Rider에 열린 코드가 대상이면 get_all_open_file_paths로 실제 열린 파일을 확인하고 IDE 내용과 저장된 파일의 차이를 고려한다. 단순 보고서 작성은 열린 파일만으로 범위를 강제하지 않으며 관련 구현도 읽을 수 있다.
- 제공 코드만으로 작성하라는 요청이면 그 자료를 기준으로 작성한다. 자료에서 확인되지 않은 구현이나 테스트 결과를 보태지 않는다.
- 참고 페이지가 제공되면 연결된 도구로 읽고 제목, 밀도, 문체, 코드·사진 배치를 참고한다. 읽기 도구에서 접근이 안 되면 지원되는 브라우저로 확인한다. 끝내 읽지 못하면 참고하지 못한 사실을 밝히고 사용자가 지정한 형식을 따른다.
- 기본 참고 예시는 애니메이션 블루프린트 보고서 https://app.notion.com/p/402f82d634ba80c5b850c90597e52163 이다. 사용자가 별도 참고를 주면 그 자료를 우선하며, 매번 이 페이지 조회를 필수로 만들지는 않는다.

## 기존 보고서의 누적 갱신

- 사용자가 보고서를 작성·갱신할 Notion 페이지 링크를 주면 해당 페이지의 기존 본문을 실제로 읽고 보고서의 기반으로 사용한다. 단순 형식 참고용이라고 지정한 페이지는 내용 통합 대상과 구분한다. 목적이 불명확하면 대화 맥락으로 판단하고 대상이 달라질 때만 확인한다.
- 페이지의 기존 구현 내용, 핵심 코드, 문제 해결 기록, 관련 링크를 현재 코드·대화·Git 변경과 대조하여 새 내용을 합친다. 기본 결과는 새 내용만의 추가분이 아니라 사용자가 한 페이지에 교체하여 붙일 수 있는 통합된 전체 본문이다. 추가분만 요청하면 그 요청을 따른다.
- 구현이 여러 날에 걸쳐 진행되었어도 하나의 기능 보고서 안에서 누적한다. 날짜나 기간 지정은 새로 조사할 작업 범위에 적용하며, 기존 페이지의 이전 기록을 자동으로 제외하는 조건으로 삼지 않는다.
- 기존 설명이 유효하면 유지하고, 같은 파일·함수·내용은 중복 없이 합친다. 현재 구현과 다른 과거 코드는 최종 코드로 갱신한다. 이전 방식은 해결 원인 설명에 필요한 경우에만 과거 구현임을 밝혀 남긴다.
- 기존 본문과 현재 자료가 충돌하면 현재 파일, 브랜치와 변경 기록을 확인한다. 자료만으로 최신 여부를 확정할 수 없으면 임의로 기존 사실을 삭제하거나 새 제안을 구현 완료로 바꾸지 않고 불확실한 항목을 별도로 표시한다.
- 기존에 첨부된 사진·영상·캡션의 위치와 역할을 확인한다. 채팅에 미디어를 그대로 전달하기 어렵다면 본문에 `기존 사진 유지: ...`로 해당 위치를 명시하고, 새 자료가 필요한 위치에는 `첨부 권장 사진: ...`을 작성한다. 기존 사진을 새로 촬영해야 하는 것처럼 안내하거나 만료되는 미디어 URL을 영구 링크로 사용하지 않는다.
- 페이지가 잘리거나 접근되지 않으면 기존 본문을 읽지 못한 사실과 범위를 알린다. 확인 가능한 신규 구현 초안은 작성할 수 있지만, 기존 내용까지 보존한 누적 갱신본이라고 주장하지 않는다. 누적본 완성에 필요한 기존 본문 제공 또는 접근 가능한 링크를 요청한다.
- 링크 제공은 페이지 읽기와 통합본 작성 요청이며 게시 권한을 뜻하지 않는다. 기본 결과는 채팅에 제공한다. 실제 갱신을 명시적으로 요청받은 경우에만 쓰기 직전에 페이지를 다시 읽어 동시 편집을 확인하고, 관련 도구 지침에 따라 기존 미디어·속성과 무관한 내용을 보존하여 수정한다.

## 보고서 형식

- 바로 붙여 넣을 수 있도록 본문은 '~이다', '~하였다', '~하도록 구성하였다' 형태로 작성한다. 대화형 서문이나 제안형 튜토리얼로 시작하지 않는다.
- 제목과 구현 결과를 짧게 제시하고, 핵심 코드는 `#### TBPlayer.cpp`처럼 실제 확장자를 포함한 파일명 제목 아래 언어를 지정한 코드 블록으로 제공한다.
- 원본 코드를 정확히 발췌한다. 식별자·조건·수치·주석을 보고서용으로 임의 변경하지 않는다. 완전한 파일이 아니라 일부 멤버·함수만 발췌했다면 해당 사실을 블록 바깥에서 밝힌다.
- 독자가 변경 의도를 이해할 만큼의 선언과 함수만 담는다. 상용구 include, 단순 getter, 무관한 입력 처리, 긴 전체 파일을 반복하지 않는다. 설명에 필요하면 같은 파일을 기능별로 나눠 발췌할 수 있다.
- 각 구현은 목적과 결과를 짧게 설명한다. 문제 해결 부분은 증상, 확인한 원인, 최종 수정의 관계를 기술하며 폐기한 코드는 기본적으로 싣지 않는다.
- ABP 전이 조건 등 에디터 설정은 C++ 소스인 것처럼 제시하지 않고 상태명별 text 블록 또는 표로 정리한다. 대화에서 확인한 설정인지 실제 에셋에서 확인한 설정인지 근거 범위를 유지한다.
- 관련 위치에 `첨부 권장 사진: ...`을 넣는다. 상태 머신 전체, 전이 규칙의 조건, 입력 동작 비교 등 검증에 필요한 화면과 촬영 포인트를 구체적으로 적는다. 직접 사진을 생성·캡처·첨부하는 것은 별도 요청이 있을 때만 수행한다.
- 사용자가 제공한 개발노트 링크가 있으면 포함할 수 있다. 모르는 링크, 완료율, 담당자, 성능 수치, 빌드·멀티플레이 테스트 통과 여부는 만들어 내지 않는다.

## 작업 경계

- 이 스킬은 보고서 작성용이다. 소스 주석 추가, 변수·함수 위치 변경, 기능 수정, 커밋·push는 별도 지시 없이는 수행하지 않는다.
- Notion 문서를 참고하는 것은 읽기만 허용한다. 기본 결과는 채팅으로 제공하며, Notion 페이지를 생성·수정하지 않는다. 사용자가 게시까지 명시적으로 요청하면 대상과 범위를 확인하여 해당 도구로 처리한다.
- 보고서를 파일로 저장하는 것은 요청받았을 때 수행한다. 채팅 보고서를 위해 불필요한 문서 파일을 저장소에 만들지 않는다.

## 전달 전 확인

- 누적 갱신 시 기존 페이지의 유효한 내용과 링크·사진 위치가 보존되고 신규 내용이 중복 없이 반영되었는지 확인한다.
- 파일명, 클래스명, 발췌 코드가 현재 원본과 일치하는지 확인한다.
- 이번 작업과 무관한 이전 코드가 핵심 변경으로 표시되지 않았는지 확인한다.
- 실제 구현, 에디터 설정, 향후 계획, 사용자 확인 결과와 에이전트의 검증을 구분한다.
- 사진 안내는 글로만 남기고, 사용자가 한 번에 복사할 수 있는 완성된 본문을 제공한다.
