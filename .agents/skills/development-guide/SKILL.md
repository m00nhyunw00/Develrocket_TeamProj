# 개인 개발 가이드

사용자가 문서를 따라 직접 기능을 구현할 수 있도록 코드와 설명을 적용 순서대로 작성한다. 기본 산출물은 채팅에서 한 번에 복사하여 노션에 붙여 넣을 수 있는 완성된 Markdown 본문이다.

## 요청 범위

- 개발 가이드, 구현 가이드, 코드를 어디에 어떻게 추가하는지에 대한 적용 절차 요청에 사용한다. '노션에 복붙 가능하게'라는 표현만으로 문서 종류를 판단하지 않고 실제 요청 목적을 따른다.
- 보고서나 개발 노트의 작성·갱신 요청에는 이 스킬을 적용하지 않는다. 기술의 개념·장단점·도입 기준만 설명하는 요청을 구현 튜토리얼로 확대하지 않는다.
- 가이드 작성만 요청한 경우 프로젝트 소스·에셋을 수정하거나 문서 파일을 저장하거나 Notion에 게시하지 않는다. 직접 적용·저장·게시가 함께 요청되면 그 요청 범위에 맞춰 수행한다.

## 작성 근거

- 프로젝트 기능에 대한 가이드라면 관련 코드와 설정을 확인하고 실제 클래스명, 함수명, 기존 처리 흐름에 맞춰 작성한다. 재사용할 부분과 새로 작성할 부분을 구분한다.
- 현재 구현된 내용, 제안하는 변경, 에디터에서 설정할 내용과 실행 확인 여부를 구분한다. 제안한 코드를 이미 구현·검증한 결과처럼 표현하지 않는다.
- 버전에 따라 달라지는 API나 동작은 프로젝트 버전과 공식 문서·설치된 소스 등 확인 가능한 근거로 검토한다. 확인하지 못한 전제는 적용에 영향을 주는 범위만 짧게 밝힌다.
- Unreal에서는 BP 원본과 레벨 인스턴스, 컴포넌트와 자식 액터를 구분하고 변경 대상과 영향 범위를 설명한다. 멀티플레이 기능은 서버 판정과 클라이언트 표현의 실행 위치를 명시한다.

## 구성과 문체

- 본문은 '~이다', '~한다', '~하도록 구성한다' 형태로 작성한다. '~입니다', '~하세요', '~해줘' 같은 존댓말·대화체를 사용하지 않는다.
- 구현할 결과와 권장 구조를 짧게 설명한 뒤, 필요한 선행 설정 → 코드 추가·교체 → 에디터 연결 → 동작 확인 순서로 구성한다. 기능에 필요 없는 항목까지 고정 목차로 채우지 않는다.
- 제목, 번호 목록, 표, 언어를 지정한 코드 블록을 사용하여 노션에서 읽기 쉽게 작성한다. 문서 전체를 하나의 코드 블록으로 감싸지 않는다.
- 파일 안내는 `TBPlayer.cpp`처럼 확장자를 포함한 파일명만 쓴다. 제목·본문·표의 파일 안내에 절대 경로, 상대 디렉터리 경로, 파일 링크를 넣지 않는다. 동명 파일은 클래스·역할로 구분한다.
- 컴파일에 필요한 `#include` 경로, 실행에 필요한 명령 인자와 에셋 참조는 코드 안에 그대로 유지한다. 코드 밖의 파일 안내와 구분한다.
- 사진·영상 첨부란, 촬영 안내, '첨부 권장 사진' 문구를 넣지 않는다. 보고서의 고정 도입 문구, 개발 노트 링크 자리, 완료 실적 항목도 넣지 않는다.
- 배경 이론이나 대안 나열보다 구현에 필요한 설명을 우선한다. 선택 이유와 적용 시 달라지는 동작은 해당 코드 가까이에 짧게 설명한다.

## 코드와 설명

- 각 코드 블록 앞에 파일명, 새 파일 작성인지 기존 코드 수정인지, 넣을 클래스·함수·접근 지정 영역을 명시한다. 기존 코드 수정은 추가 위치와 교체 범위를 구체적으로 설명하여 중복 선언·중복 호출을 방지한다.
- 새 파일은 적용에 필요한 전체 코드를, 기존 파일은 수정에 필요한 완결된 선언·함수·블록을 제공한다. 무관한 기존 파일 전체를 반복하지 않는다.
- 직접 복사하여 적용할 코드에서 필요한 로직을 `...`나 '기존 처리'로 생략하지 않는다. 개념 설명용 일부 발췌라면 그 사실을 블록 밖에 명시하고 적용용 코드와 구분한다.
- 필요한 include, 전방 선언, 멤버 선언, 함수 정의, 호출부, 모듈 의존성 및 등록 설정을 빠뜨리지 않는다. 이미 존재하는 항목은 재사용한다고 설명한다.
- 제공하는 모든 코드 블록에 간결한 한국어 설명 주석을 포함한다. 주요 변수·속성·함수·분기·처리 단계의 역할과 필요한 이유를 주석으로 설명하고, 의미 있는 처리에 설명이 빠지지 않도록 한다. JSON처럼 주석을 지원하지 않는 형식은 유효한 문법을 유지하고 바로 아래에 필드별 설명을 제공한다.
- 코드 블록 뒤에는 해당 변경으로 연결되는 동작과 다음 단계에서 설정할 값을 설명한다. 주석을 문장 그대로 반복하는 설명은 줄인다.
- 에디터 설정은 코드와 구분하여 대상 BP·컴포넌트·에셋, 설정 이름과 값, 연결할 항목을 표나 순서 목록으로 제시한다. 예시 에셋명은 실제 존재하는 에셋명과 구분한다.
- 코드에서 읽는 태그·소켓·파라미터 이름은 선언, 호출부와 에디터 설정에서 일치하도록 작성한다. 기본값, 재생 수명, 정리 처리가 구현에 필요한 경우 함께 다룬다.

## 전달 전 확인

- 기존 코드부터 최종 에디터 설정까지 순서대로 따라갔을 때 요청한 결과를 만들 수 있는지 확인한다.
- 추가·교체 위치가 명확하고 선언·정의·호출·설정 이름이 일치하는지 확인한다.
- 코드 주석, 파일명만 사용하는 안내, '~이다' 문체가 적용되었으며 사진 첨부란이나 보고서 양식이 섞이지 않았는지 확인한다.
- 기능의 정상 동작과 주요 경계 상황을 확인할 방법 및 기대 결과를 짧게 제공한다. 실제 수행하지 않은 빌드·실행·멀티플레이 검증을 통과했다고 쓰지 않는다.
